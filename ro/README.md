# ro/ — 模拟支线：7 级环形振荡器（手工版图 → PEX → 优化）

这是 `openlane-lab` 数字主线之外的一条**模拟支线**：不用综合、不用 APR，纯手工画一个
7 级反相器环振，走完 **原理图 → 前仿 → 版图 → 提取寄生 → 后仿 → LVS → 迭代优化**。

| 项 | 值 |
|---|---|
| 工艺 | SKY130A（`sky130_fd_pr`，1.8 V 器件） |
| 器件 | `nfet_01v8` W=1 µm / `pfet_01v8` W=2 µm，L=0.15 µm |
| 拓扑 | 7 级反相器闭环，输出 `out` |
| 工具 | xschem（原理图）、ngspice（仿真）、magic（版图/提取/DRC）、netgen（LVS）、KLayout（渲染） |

## 1. 一条命令复现

```bash
bash ro/run_ro.sh              # 前仿 → 版图+DRC → PEX → 后仿 → LVS → 渲染
bash ro/run_ro.sh --corners    # 额外跑 tt/ss/ff × -40/25/100°C
```

可用环境变量覆盖：`RO`（工作目录，默认 `~/asic_ro/run`）、`OUT`（结果目录，默认 `ro/out/serp`）、
`PDK_ROOT`、`PDK`、`MAGIC`、`NETGEN`。脚本会自动找 Nix 里的新版 magic（apt 的 8.3.105
读不了 sky130 techfile）和 netgen，并设置 `NETGENDIR`。

成功标志：

```
DRC 0；LVS Circuits match uniquely；后仿 ~2.19 GHz；损耗 ~27.6%
```

## 2. 流程

```
ro.sch ──xschem──► ro.spice ──ngspice──► 前仿 3.020 GHz
                                    │
                    版图（magic，逐层矩形；gen_serp.py 生成 TCL）──► DRC
                                    │
                              extract all ──► 带寄生 SPICE
                                    │
                       ngspice 后仿 ──► 频率 / 损耗 / corner
                                    │
                     netgen LVS（对照 ro_schem.spice）──► match uniquely
```

## 3. 结果（统一口径：5 ps 步长、相邻上升沿）

| 版本 | 改动 | 布局尺寸 | 后仿频率 | 寄生损耗 |
|------|------|----------|-----------|----------|
| v5 | 单排 7 级 | 25.4 × 6.0 µm | 1.897 GHz | 37.2% |
| R1+R2 | 布线收紧 + 源漏结面积最小化 | 18.7 × 6.7 µm | 2.134 GHz | 29.3% |
| **R3** | **两排蛇形 floorplan** | **11.1 × 11.5 µm** | **2.187 GHz** | **27.6%** |

前仿（无寄生）**3.020 GHz**；2 ps 复核 3.029 GHz / 2.190 GHz（差 < 0.3%）。
累计 **+15% 频率，损耗压低 9.6 个百分点**；每版 **DRC 0**、**LVS 14 器件 / 9 网络 match uniquely**。

> 历史版本号 R1（布线收紧）没有单独存档网表，`ro_opt` 是 R1+R2 的合并结果；
> 旧文档里的 835.7/882.0/910.8/952.2 MHz 是「3 个周期 + 50 ps 步长」的旧口径，见 §4。

### 蛇形版做了什么

- 下排 cell0–3 正常朝向，上排 cell4–6 **旋转 180°**，管脚全部朝向中间布线通道；
- 反馈网（cell6 → cell0）从 ~25 µm 缩到 **4.4 µm**；
- 电源轨用 met2 竖带在右侧跨行缝合；
- 版图从 25.4×6.0 的长条变成 11.1×11.5 的方形，级间布线长度减半。

### corner 扫描（PEX 后仿，5 ps 步长）

| corner | −40 °C | 25 °C | 100 °C |
|--------|--------|-------|--------|
| tt | 2243.0 MHz | 2188.6 MHz | 2128.3 MHz |
| ss | 1463.6 MHz | 1544.3 MHz | 1601.1 MHz |
| ff | 3055.2 MHz | 2906.5 MHz | 2686.7 MHz |

- ff/ss 跨度约 **2.1×**（ff 25 °C 2.91 GHz ↔ ss −40 °C 1.46 GHz）；
- tt/ff 随温度升高变慢（迁移率下降），ss 在本偏置下反而随温度变快（Vth 下降占主导）；
- 结论：**环振频率对工艺角比对温度敏感得多**，这也是它适合做工艺监控的原因。

## 4. 测量口径（两个坑，必须知道）

1. **周期数**：`rise=4 → rise=10` 之间是 **6 个周期**，不是 3 个。原脚本 `3/(t2-t1)` 把频率
   算小了一半（835.7/882.0/910.8/952.2 MHz 这组历史数字就是这么来的）。
   现在脚本用 `r10 → r50`（40 个周期）计算，并用相邻沿交叉验证。
2. **时间步长会锁相**：`tran 0.05n` 对 ~500 ps 的周期只有 10 个点，ss 角被锁在
   700.0 ps（14×50 ps）上，而且三个温度给出完全相同的频率。
   改成 **5 ps** 后 ss 才恢复温度敏感性（1463.6/1544.3/1601.1）。经验：步长 ≤ 周期的 1/50。

## 6. 已知局限

1. **手工单元，不是 stdcell**：每个反相器是逐层矩形拼出来的，没有标准单元库的
   pin/密度/天线规则。
2. **PEX 只有一套 RC 模型**：corner 是换 liberty/温度，不是换 RCX 模型。
3. **没有 MC / 相位噪声 / 功耗分析**：环振在这里当延迟标尺，主要看周期。
4. **`scripts/` 里的旧脚本是当时环境原样**（WSL `~/asic_ro`），入库时脱敏了路径；
   日常复现请用 `run_ro.sh`。
